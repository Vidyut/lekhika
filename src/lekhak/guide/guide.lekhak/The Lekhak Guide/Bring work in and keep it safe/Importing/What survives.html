Information that is present in the imported markdown can be brought in, but it is your responsibility to ensure the file contains what you need. Metadata included in YAML blocks can be read into fields; the rest of the content is imported as text.

When a YAML value is read, Lekhak chooses a field type from what it sees: an ISO date becomes a Date field, true or false becomes a Checkbox, and anything else is Text. This recognition can be wrong; you can change a field's type afterwards if needed.

Some names are handled specially during import. Template and Template config are treated as design markers rather than ordinary metadata fields. Type is kept as the document’s role. If imported names conflict with names Lekhak reserves, the result may need adjustment after import.

Project-level keys (such as Author, Title or Copyright) fill the project's own fields only where you have not already set them. Values you have already set are kept.

Markdown import has not been robustly tested across every writing tool and export style. It is included because writers often need to bring existing projects in, but mapping one customisable tool’s export to another’s structure can be complicated. Expect to review and tweak the result, especially for heavily customised projects, and report problems on GitHub if you run into them.
