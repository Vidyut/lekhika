--- title: Folders, documents and their types kind: scene page_break: auto ---

Lekhak does not insist on a shape for your project. It contains folders and document files that can be dressed up to suit what you want to create. You may be writing a book, and put your chapters as files in it without any folders. You may be writing a series, and have folders for books and even chapters, with each chapter containing a few scene documents. You could be writing a recipe book, with some documents as chapters with regular text, while others are recipes that need specific formatting.

That's why we have types and templates. There are no default types. By default, folders are folder and documents are documents - these types are the bare minimum and baked into Lekhak, even if you never use them.

Simply put, a type is a role a folder or document plays. Lekhak tracks types for folders and documents separately, as they are inherently different and not interchangeable. A folder type "book" can be applied to other folders, but not to documents. A document type recipe could be applied to other documents, but not folders. A project could contain only standalone flashfiction stories if you wish. You decide what you're writing and how you organise it.

Types can be set in the metadata on the right where the collapsible menu says "Formatting related". A dropdown offers you the types that have been created in the document and next to it, a text box allows you to add a type. If the type exists for what you intend to do, you should select it rather than create a new one, as it will keep your templates manageable.

To style types, so that they can serve their intended purpose, you should use templates. A template document with the same name as the type will be selected by default and you don't need to do anything further. If there is no template that matches the type, and the metadata for a folder or document also doesn't assign one in the metabox, the folder and document templates are used by default.

The Type field is protected: you change it deliberately, and templates and the UI read it rather than anything else. A document that should not appear in an export at all can be given the no-export template (or the no-export set), which prints nothing — without a separate kind to choose by mistake.

A row in the binder is moved by dragging it: drop it between two rows to place it exactly there, or onto a folder to put it inside. If a move cannot happen — usually because the destination already holds a file of that name — nothing is written and the binder is put back the way the files are. Lekhak would rather say no than quietly rename something you made.

You can find out more about templates later.
